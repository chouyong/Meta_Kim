2. The equality assertion cannot trivially pass. Lines 220-235 combine four independent guards: same-key for the six variants (`-cne`), distinctness for `$nameA` vs `$nameB`, drive-root normalization preserving `D:\` meaning plus slash-variant agreement, a strict `^Local\\CodexClaudeCliProjectChainV2-[0-9a-f]{64}$` shape check, and a path-leak check. A degenerate identity function returning a constant fails the `$nameA -ceq $nameB` guard; one returning the raw path fails the shape and leak guards. Comparisons correctly use case-sensitive operators against a lowercase digest.
3. Concurrency is genuinely cross-process. The holder is an in-process `System.Threading.Mutex` acquired with `WaitOne(0)` (248-250); the probes are separate `powershell.exe` processes launched via `ProcessStartInfo` with a base64-embedded script (22-86). Same-project expects exit 23, which the probe emits only from `-not $hasMutex` (line 45); different-project expects exit 0 after a successful acquire and release. `Local\` is session-scoped and both processes share the session, so the contrast is meaningful rather than an artifact of namespace mismatch. Probe start failure and the 10 s timeout throw rather than returning 23 or 0, so neither expectation has an obvious false-positive path.

## Residual Risks

- Invoker binding is substring presence only. It proves the three invokers reference the V2 helper and no longer reference the V1 mutex name; it does not prove the mutex is acquired around the model call, held for the call's duration, or that `$root` at that call site equals the project root. The mode label is honest about this, but the cross-direction guarantee remains weaker than the same-key and blocking guarantees.
- Identity keyed on volume serial plus file index is stable for a live directory but not durable across delete-and-recreate of the same path, and can in principle be reused after deletion. Irrelevant to these four cases; relevant to any future claim of key stability over time.
- The drive-root assertion checks normalization and slash-variant agreement but never asserts `$driveRootName -cne $nameA`, so a drive-root/child collision would not be caught by that specific guard.
- `equivalent-windows-directory-aliases` says "junction or other handle-resolved alias"; only a junction is exercised. The generalization is mechanism-plausible given file-index identity but is untested for symlinks, `subst` drives, mapped network paths, and hardlink-style aliases.
- The uppercase variant uppercases the entire path including the temp GUID; this is safe on case-insensitive NTFS but the probe would not distinguish a case-sensitive-directory-enabled volume.
